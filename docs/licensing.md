# Licensing Policy — read before training or shipping anything

Most publicly available signature verification assets are restricted to
non-commercial research use. Using them to back a production deployment
would be a licence breach. This is the single most likely thing to derail the
project *after* a successful POC, because the problem surfaces at procurement
time rather than at build time.

## Asset status

| Asset | Licence reality | Verdict |
|---|---|---|
| `luizgh/sigver` **source code** | BSD-3-Clause | ✅ Commercial use fine |
| `luizgh/sigver` **pretrained weights** | Trained on GPDS → non-commercial only | ❌ Track A only |
| **GPDS-960** | Withdrawn under GDPR, no longer distributed | ❌ Unavailable |
| **GPDSsynthetic** | Available on request, non-commercial research licence | ❌ Track A only |
| **CEDAR** | Research use | ❌ Track A only |
| **UTSig / BHSig260 / SigComp / MCYT / SID** | Research use | ❌ Track A only |
| `tech4humans/yolov8s-signature-detector`, Ultralytics YOLO | AGPL-3.0 (viral) | ❌ Needs Ultralytics Enterprise licence, or use a permissive detector |
| torchvision detectors (Faster R-CNN, RetinaNet), DETR/RT-DETR | BSD-3 / Apache-2.0 | ✅ Commercial use fine |
| Signatures you collect yourself | You own them | ✅ Track B |
| `ml/data/synth.py` output | Generated by this repository | ✅ Track B |

## Pretrained models: the distinction that matters

The rule is **not** "no pretrained weights". It is "no weights whose training
data was licensed for research only". Those are different, and conflating them
cost this project real accuracy: the first model was trained from scratch on 84
writers when a permissively-licensed pretrained backbone was available all
along.

| Pretrained asset | Licence | Production |
|---|---|---|
| SigNet / `sigver` weights | GPDS-derived, non-commercial | ❌ Never |
| **DINOv2** (`facebook/dinov2-*`) | **Apache-2.0** | ✅ Yes |
| **SigLIP** (`google/siglip-*`) | **Apache-2.0** | ✅ Yes |
| **CLIP** (OpenAI) | **MIT** | ✅ Yes |
| TrOCR | MIT | ✅ Yes |
| ImageNet torchvision weights | ImageNet terms are research-oriented | ⚠️ Avoid |

Signature-*specific* pretrained weights are the poisoned ones, because the only
large signature corpora are research-licensed. General-purpose vision
foundation models carry no such restriction, and fine-tuning one with LoRA is
both legal and — on a small corpus — considerably more accurate than training
from scratch. See `ml/embed/backbones.py`.

Two operational notes:

- `ml/tests/test_backbones.py` asserts every backbone declared in
  `BACKBONES` is commercially licensed. Adding a non-commercial one fails CI.
- Hub weights must be pre-staged for an air-gapped datacentre: download once on
  a connected machine, copy the cache, then set `HF_HOME` and `HF_HUB_OFFLINE=1`.

## The two-track rule

**Track A — research.** Any dataset or weight above marked non-commercial.
Legitimate uses: proving feasibility, the employee demo, architecture
selection, and the vendor bake-off. Never a shipped weight.

**Track B — production.** Only (a) signature data you own and (b)
permissively-licensed or locally generated synthetic data. Every deployed
weight must be Track B.

## How this is enforced in code

- `ml/config.py` lists `NON_COMMERCIAL_SOURCES`. `ml/data/ingest.py` tags every
  ingested record with its source, and the manifest carries a `licence_track`
  field per record.
- `ml/data/manifest.py` exposes `assert_track_b(records)`, which raises if any
  record originates from a non-commercial source.
- `ml/embed/train.py` requires `--track {a,b}`. With `--track b` it calls
  `assert_track_b` before the first optimizer step, and refuses to initialise
  from Track A pretrained weights.
- Every checkpoint written carries provenance metadata: licence track, source
  datasets, signer counts, git commit, and timestamp. `ml/embed/provenance.py`
  can re-verify a checkpoint before deployment.

## Action required in Phase 0

1. Legal sign-off on the two-track split, in writing.
2. Decide the Stage A detector route: permissive architecture trained on
   your own annotated forms (recommended), or purchase an Ultralytics Enterprise
   licence.
3. Data-protection sign-off for the internal skilled-forgery collection
   exercise, including participant consent.
4. Confirm any commercial engine evaluated in the bake-off can run **on your
   own infrastructure**. If it requires sending signature images to a vendor
   cloud, that is a data protection decision, not an engineering one.
